# VAYUBODHAK Web Application Showcase Walkthrough

## 1. Overview & Objective

This document outlines the exact, repeatable demonstration procedure for the **VAYUBODHAK Web Application**. It verifies that:
1. All analytical assessments are generated by the real backend analytical engines.
2. The UI responds dynamically to operational event change detection.
3. Decision revisions evolve deterministically ($0.50H + 0.30E + 0.20V$).
4. Offline resilience and recovery seamlessly preserve verified disaster state without crashing or claiming stale data is live.
5. The presentation is visually identical to the Android application in layout language, color tokens, and terminology.

---

## 2. Pre-Showcase Setup

1. **Launch the Backend:**
   ```powershell
   # In terminal 1:
   .\.venv\Scripts\Activate.ps1
   uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

2. **Launch the Web Frontend:**
   ```powershell
   # In terminal 2:
   cd web
   npm run dev
   ```

3. **Open the Web Browser:**
   Navigate to `http://localhost:3000` (Redirects to `http://localhost:3000/overview`).
   Verify the screen resolution is set to **1440 × 900** or **1920 × 1080** for optimal recording.

## 3. Step-by-Step Demonstration Script

### Step 0: Initial Nominal State & Provenance Check
* **Observe Top Header**: District displays "Gwalior District, MP", status indicator displays `● FULL_OPERATIONAL`, source attribution displays `LIVE` (or `CACHED` if offline).
* **Observe Intelligence Pipeline**: 7 stages (Evidence → Hazard → Exposure → Vulnerability → Risk → Impact → Nirnay) are rendered in nominal green/neutral states.
* **Click through Pipeline Stages**: Notice how clicking each stage highlights structured telemetry parameters without page reloads.

### Step 1: START Showcase Scenario (Baseline)
* **Action**: Click the green **"START"** button on the ShowcaseBar at the top of the screen.
* **System Action**: Calls `POST /api/v1/internal/showcase/start`.
* **Visual Updates**:
  * Step badge transitions to: `Step 0: Baseline`.
  * Weather Card displays baseline conditions (Precipitation: 0.0 mm, Wind: 14 km/h).
  * Risk Card reflects baseline score ($0.18$ - LOW).
  * Nirnay Card displays verdict `MONITOR` with severity `LOW`.
  * Status indicator reflects `CONTROLLED_SCENARIO` attribution.

### Step 2: NEXT — Precipitation Surge (Change Detection)
* **Action**: Click the **"NEXT"** button on the ShowcaseBar.
* **System Action**: Ingests high-precipitation telemetry event. Change detection activates selective recalculation.
* **Visual Updates**:
  * Step badge transitions to: `Step 1: Rain Escalation`.
  * Weather Card precipitation jumps to $48.5\text{ mm/h}$ (Torrential).
  * Hazard Card updates score to $0.62$ (MODERATE).
  * Nirnay Card updates verdict to `PROCEED_WITH_CAUTION` with yellow severity container.
  * Recommended action instructs immediate drainage clearance and operational standby.

### Step 3: NEXT — Statutory Warning Bulletin (Threshold Escalation)
* **Action**: Click the **"NEXT"** button on the ShowcaseBar.
* **System Action**: Statutory warning event received from NDMA/IMD feeds.
* **Visual Updates**:
  * Step badge transitions to: `Step 2: Warning Escalation`.
  * Composite risk index increases to $0.74$ (HIGH).
  * Nirnay Card transitions to `POSTPONE` with orange warning container.
  * Action window scanner indicates operational feasibility has closed.

### Step 4: NEXT — Nirnay Revision & Notification Broadcast
* **Action**: Click the **"NEXT"** button on the ShowcaseBar.
* **System Action**: Final decision revision computed. Notification engine broadcasts high-priority alert.
* **Visual Updates**:
  * Step badge transitions to: `Step 3: Nirnay Revision`.
  * Nirnay Card displays `NO_GO` verdict with bold red container.
  * Navigate to `/alerts`: High-priority alert banner `CRITICAL: Heavy Inundation Warning` is rendered at the top of the event stream.
  * Open Nirnay Card Ledger: Rule `R-STATUTORY-PRECIP` indicates `FAILED`, verified by SHA-256 ledger signature.

### Step 5: Offline Resilience Demonstration
* **Action**: Stop the backend process (or simulate network disconnect in browser DevTools Network $\to$ Offline).
* **Visual Updates**:
  * System Status indicator smoothly shifts to `■ OFFLINE Mode Active`.
  * Source Attribution shifts to `CACHED`.
  * Last verified timestamp is preserved.
  * The Nirnay card, weather observations, and risk matrix **remain visible and fully interactive**. No white-screen crash or technical 500 error is presented.

### Step 6: Recovery Demonstration
* **Action**: Re-enable network / restart backend process, then click **"Force Sync Now"** on `/system-status`.
* **Visual Updates**:
  * Indicator briefly shows `◆ RECOVERING`.
  * Replays incremental operational events from cursor sequence.
  * Smoothly restores `● FULL_OPERATIONAL` state.
