## 1. Contract Design Principles & Type Rigor

All WeatherGPT communication interfaces (Client $\leftrightarrow$ Backend, Gateway $\leftrightarrow$ Brains, Tool Gateway $\leftrightarrow$ Services) adhere to strict, versioned JSON schemas validated using Pydantic v2.

1. **Explicit Timestamps & Offsets:** All timestamps must follow ISO 8601 with explicit timezone offsets (e.g., `2026-08-29T11:30:00+05:30` or `2026-08-29T06:00:00Z`).
2. **Strict Metric Units:** Standard scientific/meteorological units are enforced:
   * Temperature: Celsius (`°C`)
   * Precipitation: Millimeters (`mm`)
   * Wind Speed: Kilometers per hour (`km/h`) or Meters per second (`m/s`)
   * Pressure: Hectopascals (`hPa`)
   * Spatial Reference: WGS 84 (`EPSG:4326`)
3. **No Silent Defaults:** If a mandatory field (such as location or target temporal window) cannot be resolved, the pipeline must return a structured validation or clarification error rather than inventing default coordinates.

## 6. Null & Error Handling Rules

1. **Null Omission vs. Explicit Null:** Optional top-level fields (`recommendation`, `alert`, `visualizations`) must be set to `null` or `[]` if inapplicable for the query (e.g., General Brain will set `recommendation: null`).
2. **Error Payload Specification:** If an unrecoverable failure occurs during pipeline execution, the backend returns HTTP 200 with an explicit error object in the response body or a standard RFC 7807 problem detail payload for HTTP error codes.

```json
{
  "status": "error",
  "error_code": "MISSING_MANDATORY_LOCATION",
  "message": "Please specify the location or grant GPS permission to get the weather forecast.",
  "action_required": "PROMPT_LOCATION_INPUT",
  "details": {
    "field": "location",
    "suggested_cities": ["Delhi", "Mumbai", "Kolkata", "Bengaluru", "Ahmedabad"]
  }
}
```
